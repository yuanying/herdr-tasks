# 0005. タスクディレクトリに手順書への入口を置き、coordinator をそこに座らせる

- Date: 2026-09-04
- Status: Accepted（[ADR 0002](0002-task-workspace-with-repository-tabs.md) の
  「coordinator の cwd」に関する決定を改める）

## Context

ADR 0003 は再開に必要な事実をタスクディレクトリに置くことを決め、その追記は
置いた記録が腐る問題を扱った。どちらも **記録が読まれること** を前提にしている。
では誰が読ませているかというと、起動時のプロンプトである。

- coordinator も worker も、手順書とタスクディレクトリのパスを起動時のプロンプトで受け取る。
- そのプロンプトは会話文脈の一部であり、セッションのクリア・コンテキストの喪失・
  プロセスの再起動で消える。
- 残るのは、**タスクディレクトリを見る理由を持たない agent** である。プロセスは生きているため、
  herdr から見れば単に idle であり、失敗として現れない。
- 現行の復旧手順（`SKILL.md`「coordinator が停止した場合の再開」）は、
  **人間が気づいて再プロンプトすること**を前提にしている。誰も見に行かなければ、
  タスクは記録を全部揃えたまま止まる。

ADR 0003 が塞いだのは「再開に必要な事実が無い」という穴で、ここで開いているのは
**その事実へ戻る道が無い** という穴である。同じ穴の別の面であり、記録をいくら
正確に保っても閉じない。

一方、Coding Agent の多くは cwd とその親ディレクトリにある規約ファイル
（`AGENTS.md` / `CLAUDE.md`）をセッションの開始時に読み込む。ここに入口を置けば、
agent 側の記憶に依存せず、毎セッション自動で手順書へ戻せる。

ただし ADR 0002 は、呼び出し元のリポジトリが対象に含まれる場合だけ coordinator の cwd を
そのリポジトリの worktree にしていた。**この場合だけタスクディレクトリが cwd の親に
ならず、入口が届かない。** 対象リポジトリの中に置くわけにもいかない（コミットされてしまう）。
そして ADR 0004 で 1 PR = 1 worker としたことで、coordinator が自分で実装する必要は
すでに無くなっていた。残っていたのは分岐だけである。

## Decision

### 1. タスクディレクトリに入口を置く

- `$TASK_DIR/AGENTS.md` を置き、`$TASK_DIR/CLAUDE.md` はそれを `@` で読み込むだけにする。
  Claude Code は `AGENTS.md` を読まないため、この 1 行が要る。
- 生成は `scripts/write-task-agents.sh` が行い、雛形は `templates/task-agents.md` に置く。
  スキルのパスとタスクディレクトリのパスを差し込む。**冪等**であり、
  マーカー行を持たないファイル（人が書いたもの）は上書きせず中止する。
- 呼び出し元がタスクディレクトリを作る時点で生成する。この規約より前のタスクディレクトリに
  当たった coordinator は、自分で生成してから先へ進む。
- **中身は入口に徹する。** cwd から役割を見分ける表と、その役割が読む手順書のパスだけを置く。
  規律は `coordinator.md` と `worker.md` が持つ。入口は壊れたセッションだけでなく
  **毎セッション読み込まれる**ので、短いことがそのまま要件になる。
- すでに手順書を読んでいるセッションでは読み直さなくてよい、と入口自身に書く。

### 2. coordinator の cwd は常にタスクディレクトリとする

- ADR 0002 の「呼び出し元リポジトリが対象に含まれる場合はその worktree を coordinator の
  cwd とする」を改める。呼び出し元が何であっても
  `herdr workspace create --cwd "$TASK_DIR"` の 1 経路だけにする。
- **coordinator は実装しない。** 対象が 1 リポジトリでも、それが呼び出し元のリポジトリでも、
  worktree tab と worker を作る。ADR 0004 で作業単位ごとに worker を立てると決めた以上、
  coordinator だけが例外を持つ理由が無い。

## Consequences

- **セッションのクリアは自力で回復する。** これまでの再開手順が要るのは、agent プロセス
  そのものが失われた場合だけになる。人が気づくまでの時間がタスクの停止時間ではなくなる。
- worker worktree は `$TASK_DIR/worktrees/` の下にあるため、同じ入口が worker にも届く。
  ただし **親ディレクトリまで遡って規約ファイルを読むかは harness による。** 遡らないものでは
  worker の復帰は従来どおり coordinator の監視（`coordinator.md` 手順 7）が受け持つ。
  入口と監視の二重で担保する形になり、ADR 0003 の追記が報告について選んだ形と同じである。
- Claude Code は、working directory の外を指す `@` インポートに承認ダイアログを出すことがある。
  coordinator は cwd がタスクディレクトリなので出ない。worker 側で出た場合は承認するか、
  `CLAUDE.md` を `AGENTS.md` への symlink に替える。
- 単一リポジトリの小さなタスクでも tab と agent が 1 つ増える。ADR 0001 が
  「単一リポジトリ案件では余分なプロセスが立たず軽い」とした利点を捨てることになる。
  代わりに経路が 1 本になり、入口の到達範囲・片付けの手順・命名がすべて同じ形に揃う。
  **例外を 1 つ残すと、そこだけ担保が効かない。**
- タスクディレクトリに agent 向けのファイルが増える。記録の 3 ファイルと入口を混同しないよう、
  `coordinator.md` 手順 3 に「入口には進捗を書かない」と明記した。
- 入口は生成物である。**直すのは `templates/task-agents.md` 側**であり、
  既存のタスクにはスクリプトの再実行で配る。マーカーを残したまま手で直した入口は、
  次の実行で黙って上書きされる。雛形と実物が食い違う余地はここに残る。
